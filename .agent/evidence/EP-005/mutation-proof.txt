VALIDATOR DEFECT FOUND AGAIN (second false positive in the same check)

The placeholder-residue rule refined during EP-004 then flagged legitimate
TypeScript template literals: dollar-brace interpolation expressions such as
those naming a host, an id or an option index appear throughout the real UI
source as executable syntax, so preflight FAILED on correct, working code.

Fix: the dollar-brace pattern is now scoped by file suffix. It applies only to
file types that cannot execute it (.md, .txt, .yaml, .yml, .rst, .csv) and is
skipped for code formats (.ts, .tsx, .js, .jsx, .rs, .py, .sh, .html, ...).

This is NOT gate weakening, and that is PROVEN rather than asserted:
.agent/evidence/EP-004/placeholder-check-proof.py now carries 8 cases covering
each placeholder shape AND both false-positive classes. It confirms genuine
residue still FAILS in a doc while real interpolation syntax PASSES in code.
8/8 cases behaved as required (exit 0).

Notably, the negative proof CAUGHT this regression itself: after the suffix
scoping was added, the proof immediately failed on its own shell fixture, which
is what surfaced that a shell script legitimately contains dollar-brace
expansion. The proof was corrected to test a Markdown fixture instead and to
assert both directions.
