--------------------------------------------------------------------------------
TWO REAL VULNERABILITIES FOUND BY THIS ORACLE (not by mutation — by the tests
failing on first run against my own first implementation):

1. PATH TRAVERSAL ESCAPED THE SCOPED ROOT.
   "/data/drafts/../../../etc/passwd" was ACCEPTED. The first implementation
   normalized paths but preserved ".." segments while still doing prefix
   containment, so the escaping path retained the "/data/drafts" prefix.
   Fix: any normalized path still containing a ".." segment is refused
   outright. Refusing rather than resolving is deliberate — lexical resolution
   cannot account for symlinks, so an escaping path is never safe to accept.

2. UNTRUSTED TEXT COULD FORGE A SECTION HEADER.
   Untrusted content containing the literal "[INSTRUCTIONS]" produced a SECOND
   instruction section in the rendered prompt, because neutralization handled
   only code fences. A model reading the output would see two instruction
   blocks, the second attacker-controlled.
   Fix: neutralize our own structural markers inside data blocks.

Both were caught because the tests asserted the security property rather than
the implementation's happy path. Both are now covered by mutation M5 and M8.
